# 数值工坊

数值工坊是面向挂机、放置游戏的数值检查工具。填入角色、敌人和战斗规则，可以检查一场战斗。补上关卡成长、强化价格、金币收入和玩家的回访安排后，可以模拟整条推关路线，追查卡点，并比较修改前后的效果。

| 你想弄清楚什么 | 可以查看什么 |
| --- | --- |
| 为什么这场打不赢，或者打得比预期慢 | 胜负、剩余生命、逐击伤害和各阶段的结算明细 |
| 玩家卡住是因为伤害不足、买不起强化，还是下一次上线太晚 | 逐关推进、钱包余额、购买时点和未推进时间的构成 |
| 加攻击、改价格或调回访节奏，哪个方案更接近目标 | 同一组试算编号下的前后对照，包括周期、等待、花费与失败次数 |
| 工坊的计算和游戏里的实测是否一致 | 单次伤害、整场结果、升级前后属性及费用的逐项核对 |

[打开线上数值工坊](https://idle-balance-workshop-20261102.tastycamel131.chatgpt.site) · [下载本地 ZIP](https://github.com/Crimson227/idle-balance-workshop/archive/refs/heads/main.zip)

## 快速上手

1. **打开工具。** 可以直接用线上版，也可以解压仓库 ZIP 后打开 `dist/index.html`。本地使用时保留完整的 `dist/` 文件夹，表格解析组件、字体和配套页面都在其中。
2. **先查一场战斗。** 点「先查一场战斗」，填写双方生命、攻击速度、伤害和当前启用的机制，再点「计算这场战斗」。也可以先载入内置《遗迹守卫》示例。
3. **继续补长期配置。** 沿用已填的战斗数据，补充关卡、强化、金币和回访规则，然后运行「整体检查」。可以先看实际节奏，等目标明确后再填写目标。
4. **根据记录定位卡点。** 在结果页查看最长未推进的一段，展开对应战斗、购买和回访记录，再决定要调整哪条规则。
5. **比较并保留改动。** 在「解决方案」里设定允许修改的参数和范围，预览候选方案。选定后可以应用，也可以撤销已应用的方案。

### 用两关冰霜案例练手

首页的「看一个可手算的完整例子」包含一份两关配置。角色每秒攻击一次，每击有 1 点物理和 4 点冰霜伤害。敌人的冰抗为 50%，实际每击扣血 3 点。第一关敌人有 6 点生命，第二关有 8 点生命。

| 配置 | 第一关通过 | 第二关通过 | 强化支出 |
| --- | --- | --- | --- |
| 冰霜升级关闭 | 第 2 秒 | 第 5 秒 | 0 金币 |
| 启用冰霜升级 | 第 2 秒 | 第 4 秒 | 10 金币 |

启用升级后，角色在第一关结束时用首通奖励买下 1 级冰霜强化。每击冰霜伤害从 4 增至 8，经 50% 冰抗减伤后，物理和冰霜合计每击扣血 5 点。第二关少打一击，整条路线快 1 秒。[两关冰霜升级配置](source/connected-core/冰霜手算案例.json)

## 战斗规则与逐击回放

工坊支持物理、火焰、冰霜、闪电和毒性五个伤害通道。可以为双方分别设置属性，按项目开启护甲、穿透、暴击、格挡、增伤、抗性与减抗、吸血及回复。单场结果可展开每个时刻的生命变化和伤害构成。

| 规则 | 可配置内容 |
| --- | --- |
| 直接伤害 | 固定值、区间随机值、属性倍率或受限公式，支持多段攻击 |
| 防御 | 护甲系数换算、固定抵消或直接比例减伤 |
| 暴击 | 概率、低生命必暴、未暴击保底，以及按段或按整次攻击判定 |
| 同刻出手 | 同时结算、角色先手或敌人先手。开启先手时，先手击杀会取消后手同刻的出手 |
| 暴击与防御 | 可分别设置暴击倍率与物理防御的先后顺序 |
| 伤害取整 | 保留精确值、向上取整、向下取整或四舍五入，可按每个通道或每段伤害合计处理 |
| 状态与条件 | 护盾、周期伤害、状态叠层、两种状态的反应，以及开场、攻击前、命中后的条件效果 |
| 跨战斗状态 | 可选择保留状态、暴击保底与护盾，并设置战斗间的状态计时方式 |

伤害公式和成长公式使用内置表达式。常用写法有 `attack * 0.5`、`base + step * n`，以及 `min`、`max`、`clamp`、`pow`、`floor`、`ceil`。成长公式的 `n` 从 0 开始，分别对应 0 级属性、第一次购买和第一关奖励。每段攻击按该段配置独立结算，设计多段招式时要按游戏的实际分段规则填写。

## 关卡、金币与回访

### 关卡成长和强化购买

通用模拟以首关敌人和每关属性增量生成关卡。首通奖励、强化属性和价格可以使用固定、线性、比例、分段或公式规则。每项强化可设置影响的属性、关卡解锁、前置强化和等级上限。

自动购买可以按填写顺序、当前价格、伤害或生命优先。开启「首选强化买不起时，继续找买得起的强化」后，工坊会沿用所选优先顺序查找其他可购买项。还可以设置首次挑战前先买一次强化，以及失败后等升级再试或按间隔重试。

### 固定收入和离线发奖

固定收入可以连续增加，也可以每隔一段时间到账一次。批量到账时可配置首笔时刻和批次间隔，计算购买时使用当时已经到账的金币。

| 离线规则 | 计算方式 |
| --- | --- |
| 按固定收入规则累积 | 沿用配置的固定收入方式，离线收入受时长上限约束 |
| 达到最低时长后沿用原发奖节拍 | 达到门槛后按离开时的进度续算。短于门槛或超出上限的部分暂停节拍 |
| 下次上线时一次发放 | 先按离线收益上限截取时长，达到门槛后按独立的离线每秒收入计算，可保留小数或向下取整 |

持续在线和定时回访使用同一套战斗与购买记录。定时回访可以设置每天的上线时刻、每次在线时长，以及离线是否收钱、购买和挑战。上线时刻按小时填写，从 0 开始且递增，例如 `0, 7.1, 12.2, 18.3`。其中 `7.1` 小时是第 7 小时 6 分钟，各次在线时段需要彼此错开。

### 怎么读卡点结果

- **推进曲线**记录各关通过的时点。横线表示没有新关推进，其中可以包含计划离线、战斗、等待购买、重试或换关间隔。
- **金币曲线**用于查看资源积累和到账时点，购买表可逐笔查看价格、剩余余额和强化等级。长记录的图线按区段绘制，滑块仍可查看实际记录点，购买和回访明细可翻页。
- **逐关与回访记录**用来核对到达、通过、失败、战斗和等待。遇到卡点时，可从关卡记录展开那场实际战斗，看到开打时的属性和逐击过程。

## 目标、方案搜索与实测核对

### 设定目标并比较方案

可以设置最早或最晚完成时间、最长未推进时间，以及每次回访希望通过的关数。例如，已经能打完但节奏太快时，可以设置最早完成时间。能过关但中段长时间没有进展时，可以设置最长未推进时间。

搜索前可锁定需要保留的参数，限制修改范围，并选择一次改一项、两项或三项。候选结果展示具体改动、达标情况、耗时、花费与等待变化。可以预览、应用、撤销，也可以为已有搜索追加预算，复用已完成的试算。

### 用游戏实测核对公式

在「核对我的真实算例」中填入游戏里已经测到的数值，例如第几次命中的伤害、整场胜负与耗时、双方剩余生命、升级前后的属性或实际费用。按你手里的证据填写；暂时缺少实测值的项目可以留空。工坊会按所填容差列出各项的期望值、计算值和差异。

选定方案后，可用 **30、100 或 300 对新试算编号**验证。修改前后用匹配的编号运行，查看通关比例、目标达成、耗时中位数、P95 和战斗结果。P95 用来观察较慢那一部分试算的耗时。

## 导入表格、保存和导出

支持 Excel（`.xlsx`、`.xls`）、CSV、TSV、JSON 表格，以及工坊保存的配置与结果。表格会先进入字段对应页，可以确认字段、单位和换算值，再填入游戏数据。未映射的原值可以随项目保存，留待后续处理。

下面的 CSV 可以保存为 `战斗属性.csv` 后导入。角色的 500 毫秒攻击间隔会换算为每秒 2 次攻击，敌人的 `50%` 冰抗会换算为 `0.5`。

```csv
对象,属性,数值,单位
角色,生命,100,点
角色,物理伤害,1,点
角色,攻击间隔,500,毫秒
角色,冰霜伤害,4,点
敌人,生命,6,点
敌人,物理伤害,0,点
敌人,攻击间隔,1000,毫秒
敌人,冰抗,50,%
```

| 导出项 | 适合用在 |
| --- | --- |
| 项目与字段对应 | 备份配置、表格映射和草稿，或换一台设备继续编辑 |
| 完整结果与搜索 | 复查配置、目标、试算、历史和候选方案 |
| 当前试算 | 保存正在看的单次路线。完整结果超出文件上限时，可以逐次导出 |

计算和文件读取都在浏览器中执行。项目自动保存到当前浏览器的本地存储。切换浏览器、站点地址或电脑前，可以先导出项目文件，再在新入口导入。

## 《子午线·三章远征》3.0

工坊可以直接导入游戏原版 JSON 战报。核对内容包括逐击伤害、强化价格、金币账目和逐关进度。首页的「子午线 3.0」也能直接开始整局试算，设置难度、协议、购买策略、种子、初始伤害和补给。

内置的远征规则覆盖 12 个关卡、章末领奖门槛、分档补给、首领护盾、维修蜂、过载、装备、合成、刷取和离线回访。原版战报只保存了结果与部分记录。复现某一局的手动操作时，可在「安排回访、装备与刷取」中补上已知时点。下面的例子表示在日历第 45 秒离线 90 秒。

```json
[
  {"at": 45, "action": "away", "value": 90}
]
```

复查原版时可按原版浮点判定运行，也可开启「校正极小浮点残血」观察影响。原版护盾流曾在第 6 关第 15 击后留下极小残血，导致结算到第 16 秒。开启校正后，这场在第 15 击结束。导出的工坊战报可带上模拟设置和操作计划，用于重新导入对照。

## 计算边界和验收

### 怎样解读结论

- **配置决定计算范围。** 通用战斗里，双方共用直接伤害算法和段数，各自使用自己的属性。战斗从当前最大生命开始，跨战斗继承的状态按生命周期设置计算。
- **规则缺口会标明影响。** 如果游戏机制无法用现有规则表达，可以登记缺项并注明影响战斗、成长或推荐。选择只检查已支持部分时，结果会标记覆盖范围，整体达标状态留空。
- **数字与记录可以复查。** 通用计算使用精确分数记录数值。导入既有结果时，工坊会核对逐笔余额、时间线、购买顺序和汇总。随机试算提供所选编号与样本范围内的证据。
- **超限会结束本轮计算。** 观察截止、事件预算或战斗次数上限会影响能得到的结论。达到上限时可根据中断信息缩小范围，或改用较少的试算。

### 常用上限

| 项目 | 上限 |
| --- | --- |
| JSON 导入及工坊 JSON 导出 | 单个文件 256 MiB |
| Excel、CSV、TSV 导入 | 单个文件 15 MiB |
| 表格字段对应 | 单次最多 5,000 项。工作表最多 100 列、50,000 个单元格，宽 JSON 表也会在展开前检查单元格数量 |
| 通用成长模拟 | 最多 1,000 关、90 天、单次 100,000 个事件和 10,000 场战斗 |
| 五通道强化配置 | 最多 40 个强化项目，每项最多 2,000 级 |
| 子午线 3.0 整局试算 | 观察时长最多 86,400 秒，最多 500 项手动操作 |

### 已有复测

- **子午线原版数据。** 10 份整局战报覆盖 321 场战斗、4,847 次逐击。另有 60 条定时回访路线核对过关时点和日历耗时。
- **第 40 版发布产物。** 下载线上实际提供的应用代码，在 Node 中复测 256 MiB JSON、15 MiB CSV、5,000 项 Excel、90 天回访、10 万事件，以及 432 组复杂规则。满载结果导出再导入后，事件与余额一致。[第 40 版对应提交](https://github.com/Crimson227/idle-balance-workshop/commit/99d8b403f9d388498486602608b5f5c0c8273184)
- **构建验收。** 仓库的自动测试覆盖离线发奖与可购买时间、购买顺序、十进制回访、账本核对、远征、导入导出、长记录展示和重复状态消耗。[回归测试](tests/workshop.test.cjs)

## 开发与构建

| 路径 | 内容 |
| --- | --- |
| [`dist/`](dist/) | 可直接打开的页面、配套工具与资源 |
| [`source/`](source/) | 工坊界面、样式和构建模板 |
| [`source/connected-core/`](source/connected-core/) | 战斗、成长、收入、规则检查、诊断与搜索 |
| [`source/build-assets/`](source/build-assets/) | 配置模板和辅助页面使用的计算模型 |
| [`tests/workshop.test.cjs`](tests/workshop.test.cjs) | 构建前自动运行的验收测试 |
| [`build.py`](build.py) | 运行测试并生成可发布页面 |

构建需要 Python 3.10+ 和 Node.js 22+，无须安装额外项目依赖。构建前会先运行回归测试，测试通过后才写入输出目录。

```sh
# 只运行测试
node --test tests/workshop.test.cjs

# 重建 dist/
python3 build.py

# 在单独目录生成构建产物
python3 build.py --output outputs/rebuilt

# 使用固定的本地地址预览
python3 -m http.server 8000 --directory dist
```

启动本地服务器后，可以打开 `http://localhost:8000/`。遇到可复现的问题时，保留项目配置、试算编号、触发差异的步骤与实际游戏记录，便于用同一组条件复查。

配套入口包括[配置模板与数值表](dist/02_配置模板.html)、[独立战斗诊断](dist/04_多属性战斗诊断.html)、[回访与购买策略研究证据](dist/08_回访与购买策略研究证据.html)和[补充验证说明](dist/09_补充验证与未达标说明.html)。

第三方组件的许可见 [SheetJS 许可证](source/表格导入/LICENSE.txt)和[字体许可证](source/字体许可/NotoSerifSC-OFL.txt)。
